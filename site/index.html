k kit
설치 명령 릴리스

Personal developer CLI

익숙한 Git 작업을
더 짧고 분명하게.

kit은 반복해서 사용하던 shell 명령을 하나의 Go binary로 정리한 도구입니다. 커밋 반영 상태를 비교하고, 필요한 커밋만 골라 새 브랜치에 적용합니다.

설치하기 명령 살펴보기

~/workspace/project

$ kit compare

STAT  HASH      DATE              MESSAGE
✓     329ab12f  2026-08-14 10:30  applied commit
●     a137bc91  2026-08-14 11:20  pending commit

$ kit pick feat/login --wait
Select · submit MR/PR · wait for merge

01 / INSTALL

한 줄로 설치합니다.

운영체제를 자동으로 확인하고 ~/.local/bin/kit에 설치합니다.

curl -fsSL https://kit.2juho.com/install.sh | sh

설치 script는 platform 확인, binary 다운로드, SHA-256 검증과 PATH 설정만 수행합니다. 실행 중 필요한 외부 도구는 시스템의 git뿐입니다.

02 / COMMANDS

반복 작업을 명확한 명령으로.

Git의 동작과 기록을 그대로 유지하면서 선택과 확인 과정을 간결하게 만듭니다.

01

kit compare

READ ONLY

source의 커밋이 base에 반영됐는지 cherry-pick -x 기록과 stable patch-id로 비교합니다. 기본 source는 work, base는 develop입니다.

kit compare work --base develop --limit 10
02

kit pick

GIT WRITE

최신 develop을 확인한 뒤 source의 미반영 커밋을 내장 fuzzy UI에서 선택합니다. 새 브랜치에 적용하고 push와 Gitea PR 생성까지 한 번에 처리합니다.

kit pick feat/login

space 선택 · enter 확인 · esc 취소

03

kit status

main, develop, work와 진행 중인 Gitea PR 상태를 한 화면에서 확인합니다. 서버가 느리면 --cached로 즉시 확인할 수 있습니다.

04

kit sync

merge를 확인하고 develop/work 갱신과 로컬 review 브랜치 정리를 처리합니다.

05

kit review

여러 review의 조회, 대기 또는 개별 복구가 필요할 때 사용하는 고급 명령입니다.

06

kit update

최신 릴리스를 확인하고 checksum 검증 후 현재 binary를 안전하게 교체합니다.

03 / RELEASE

현재 릴리스

main의 문서는 항상 최신 상태로 배포되고, version tag가 binary 릴리스를 갱신합니다.

첫 릴리스 준비 중 metadata 미연결
Build
—
Published
—

변경 내용

  • kit compare로 커밋 반영 상태를 비교합니다.
  • kit pick의 내장 fuzzy UI에서 적용할 커밋을 선택합니다.
  • kit sync가 merge 확인, 협업 변경 반영과 work 재구성을 처리합니다.
  • kit review는 review 대기와 개별 복구가 필요할 때 사용합니다.
  • kit update가 checksum 검증 후 binary를 갱신합니다.

환경을 확인하고 있습니다.

직접 다운로드

릴리스 metadata에서 검증된 artifact 주소를 불러옵니다. 일반 설치에는 위 설치 명령을 권장합니다.

HOW IT SHIPS

코드는 바뀌고,
설치는 그대로 간단합니다.

  1. 1
    main 반영

    기능 문서가 자동으로 갱신됩니다.

  2. 2
    version tag

    지원 OS용 Go binary를 빌드합니다.

  3. 3
    검증 후 전환

    checksum과 metadata를 함께 배포합니다.
