01 / INSTALL

한 줄로 설치합니다.

운영체제를 자동으로 확인하고 ~/.local/bin/kit에 설치합니다.

curl -fsSL https://kit.2juho.com/install.sh | sh

설치 script는 platform 확인, binary 다운로드, SHA-256 검증과 PATH 설정만 수행합니다. 실행 중 필요한 외부 도구는 시스템의 git뿐입니다.

02 / COMMANDS

세 단계로 끝내는 일상 흐름.

Git의 동작과 기록을 유지하면서, 확인·PR 생성·동기화의 세 단계만 연결합니다.

01

kit compare

READ ONLY

source의 커밋이 base에 반영됐는지 cherry-pick -x 기록과 stable patch-id로 비교합니다. 기본 source는 work, base는 develop입니다. provider API나 review metadata를 조회하지 않으며, 결과에서 바로 다음 pick 명령을 확인합니다.

kit compare work --base develop --limit 10
02

kit pick

GIT WRITE

최신 develop을 확인한 뒤 source의 미반영 커밋을 내장 fuzzy UI에서 선택합니다. 새 브랜치 적용, push와 Gitea PR Create 요청 1회를 처리한 뒤 즉시 반환합니다. PR이 Gitea에서 머지된 뒤에는 kit sync로 local Git queue를 동기화합니다.

kit pick feat/login

space 선택 · enter 확인 · esc 취소

--all 미반영 커밋 전체 선택 · --local 로컬 branch만 생성

PR Create가 실패하면 local/remote branch를 보존합니다. 재시도 전 Gitea에서 PR 생성 여부를 수동 확인하세요.

macOS login Keychain이 잠긴 일반 TTY에서는 표준 security unlock-keychain prompt를 한 번 열고 token 조회를 한 번 재시도합니다. JSON·CI·pipe에서는 먼저 대화형 terminal에서 security unlock-keychain "$HOME/Library/Keychains/login.keychain-db"로 Keychain을 수동 해제해야 합니다.

03

kit sync

Gitea에서 PR을 merge한 뒤 kit sync는 Git만 사용해 최신 base와 local work queue를 동기화하고, 향후 Kit-created marker가 기록된 review branch를 안전하게 정리합니다. provider API나 PR head는 확인하지 않습니다.

최신 develop에서 work를 재구성하고, direct first-parent 일반 pending commit만 다시 적용합니다. merge commit과 side-parent commit은 제외되며 실행 전에 경고합니다.

현재 base의 ancestor인 Kit-marked local branch만 non-force로 삭제합니다. squash merge·non-ancestor·unmarked·보호 branch와 remote branch는 보존하며, cleanup 실패는 warning으로 남고 sync는 성공합니다. 현재 branch는 정확히 origin/<branch> upstream을 추적할 때만 work로 전환해 정리합니다.

성공 뒤에도 원본 work backup branch가 남아 복원할 수 있습니다. side 작업은 work에 merge하지 말고 direct commit으로 남기거나 별도 review branch에서 관리하세요.

04

kit status · kit review

cached legacy review metadata를 확인하는 고급 명령입니다. metadata는 읽기 전용으로 남고 자동 삭제되지 않습니다.

squash merge는 cherry-pick -x와 patch-id 비교만으로 반영 여부를 확정할 수 없습니다. pending 표시가 남으면 Gitea와 Git history를 수동 확인하세요.

05

kit backup

work 재구성 전 생성된 원본 backup을 조회·복원·정리합니다. 성공한 sync 뒤에도 backup은 복구를 위해 남습니다.

06

kit update

최신 릴리스를 확인하고 checksum 검증 후 현재 binary를 안전하게 교체합니다.

변경 내용

  • kit compare로 남은 work 커밋을 확인하고 다음 pick 명령을 안내합니다.
  • kit pick은 내장 fuzzy UI 선택부터 push와 Gitea PR 생성까지 처리하고 즉시 반환합니다.
  • --all은 대량 refactor에서 미반영 commit 전체를 선택합니다. PR Create 실패 시 Gitea를 수동 확인하세요.
  • PR을 Gitea에서 merge한 뒤 kit sync가 Git만 사용해 local queue를 동기화합니다.
  • status와 review의 legacy metadata는 읽기 전용입니다.
  • kit update가 checksum 검증 후 binary를 갱신합니다.

환경을 확인하고 있습니다.
